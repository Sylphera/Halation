# Architecture

Files, the code map (file + function for each tool), export, motion and backend. Why things are the way they
are is in `docs/DECISIONS.md`.

## Files (`app/dist`)

- One file of code per tool; each file is divided into sections marked `/* ===== name ===== */` (the code map
  below names them), lowest first: a section uses only what the sections above it declare.
- Tools (one page each, loaded as an iframe by the main window): `visualizer`, `grade`, `framegrab`,
  `covertest` (`<tool>.html` + `<tool>.css` + `<tool>.js`, an ES module); `downloader`, `upscale`, `interp`, `removebg`,
  `stems` and `convert` (`<tool>.js`, a classic script).
- Main window: `index.html` + `shell.css`, `shell.js` (rail, views, Home, Library page, Settings, files and
  processes) and `services.js` (the services on `window.__hal`). Only the main window talks to Tauri.
  `atmosphere.js` (`window.__atmo`: `mode`, `navigationWave`, `current`, `variant`, `toolReview`, and `review` under
  visual tests) is plain script in three sections: navigation refraction (`bindNavigationRefraction`), the tool/page
  atmosphere (`startToolAtmosphere`, an OffscreenCanvas worker or page renderer using `soft-light.js`) and the mount
  (`div.atmo.auralis-host > .auralis-surface`, `data-mode`/`data-rest`). Home's background is `auralis.js`
  (`window.__auralis.create`): sections noise (webgl-noise simplex 3D with a 0.5 kernel, GLSL plus an allocation-free JS
  port), field (`F`: a domain-warped surface on a diagonal axis lit like silk, with a faint ripple, broad sheen and large
  voids; `height`, `surface`, `light`), grain (Halation's film grain from the previous Auralis, stationary, at half
  strength), shader (field and presentation programs), stabiliser (`stabiliserAt`: on a 24×14 CPU grid, twice a field
  second, a threshold bias and a bounded exposure hold the mean brightness at 0.054) and render (`create`). A 320px long-edge half-float field (8-bit fallback) is drawn at 15Hz; a native
  presentation pass (DPR up to 2, whole pixels) adds ±1/255 dither and the film grain over the blue noise (`blue-noise.js`,
  generated by `app/scripts/blue-noise.js`). The navigation wave and the `.auralis-wave` proxy's scale switch
  the presentation to its refraction program at 60Hz while the field stays at 15Hz. One buffer, three programs, two
  textures, one framebuffer; one texture upload. Clock delta capped at 0.1s; resize coalesced for 160ms;
  hidden/unfocused/tool/Welcome-covered views never draw; reduced motion keeps the last image and redraws only on
  invalidation (`auralisinvalidate`); context restoration keeps the phase. `canvas.__auralisState()` reports it.
  Tool pages remain transparent over the shared background.
  `jobs.js` (`window.__jobs`, `__hal.jobs`): the jobs system, every heavy piece of work of every tool waits in a
  lane there. `processes.js` (`window.__procs`): the title bar's island and its tray (the processes menu).
  `updates.js` (`window.__updates`): the updater's checks, dialogs, Activity row and Settings → Updates (docs/UPDATES.md).
- Shared by several pages: `common.js` (`window.__ui`), `i18n.js` (`t`), `icons.js`, `motion.js`, `avplay.js`
  (a video's sound in the previews: `openAudio`, Web Audio clock the picture follows),
  `tokens.css`, `ui.css`, `modules.js` (tool registry), `imgops.js` (`window.__img`: crop geometry and masks),
  `compare.js` (before / after comparator), `media.css` (Crop and Cutout dialogs), `libpanel.js` + `libpanel.css`
  (the Library panel), `bass.js` (bass envelope), `fontpicker.js`, `shim.js`, `encoder.js` (FFmpeg export),
  `spotify.js` (Spotify metadata and YouTube scoring; also loaded by the Node tests), `profile.js`
  (`window.__artist`: artist profile readers, main window only; also loaded by the Node tests).
- ES module: `grader.js` (Grade looks and grader API), `grade-color.js` (pure shared colour math and byte-exact LUT generation).
- Workers and vendored code: `grade-lut-worker.js` (one thumbnail LUT request at a time; terminated on hidden/idle), `cutout-worker.js` (Cutout model), `onnxruntime.js`, `mediabunny.js` (MP4 muxer).
- Classic scripts every page loads, in order: `i18n.js`, `common.js`, `icons.js`, `motion.js` (then `imgops.js`,
  and in the big tools `shim.js` and `fontpicker.js`). The main window then loads `modules.js`, `compare.js`,
  `encoder.js`, `shell.js`, `jobs.js`, `processes.js`, `libpanel.js`, `services.js`, `sessions.js`, `updates.js`; `shell.js` creates `window.__shell` (`S`), every part
  adds to it with `Object.assign(S, { … })`, and `window.__hal` is assembled from `S` on DOMContentLoaded.

## Shared services

Every tool reaches them through `window.__hal` (code in `services.js`, see the code map).

- Crop: one dialog for the whole app. Fixed or free ratio, move and zoom inside the frame, rule of thirds, fine
  rotation ±45°, common ratios (16:9, 9:16, 1:1, 4:5, 3:1). When a picture goes somewhere that needs a ratio
  (the Visualizer's 1:1 cover, a fixed Grade format) and does not have it, the dialog opens before it is placed;
  cancelled, nothing is placed. The first frame is centred on the subject when a Cutout mask exists. The crop is
  kept as parameters over the original and can be edited again at full quality. Used by the Visualizer, Grade,
  Upscale, Frame Grab and the Library ("Crop copy").
- Cutout model delivery (`services.js:modelFile`, `cutout-worker.js:fileChunk/takeFile`, `outfiles.rs:read_path_chunk`): authorized 512 KiB IPC responses are transferred directly to the worker with per-chunk acknowledgement. Only the worker assembles model/runtime bytes; main-thread whole-model IPC is avoided. Existing `read_path` consumers keep their behavior.
- Cutout: background removal on the machine (ONNX Runtime Web, SAM 2.1 Base+: the encoder at 1024 px once per picture, fp16 on
  WebGPU, fp32 on the CPU, and the prompt decoder per click; a downloadable
  component). One dialog: before / after with Upscale's comparator, a brush to add or remove, edge softness and
  shift, a checkerboard, black, white or colour backdrop, "Apply". Result: the picture with transparency plus the
  editable mask (cached by the picture's hash, `Tools\cache\cutout`). Used by Grade, the
  Visualizer ("Cover cutout", the subject over the frame), Upscale (Upscale → Cutout in one step, and batches
  through its queue), the Downloader's covers and the Library ("Add cutout version").
- Frame Grab's extractor: the one component that reads video frames, all through FFmpeg (the frame at its native
  size and exact index, the keyframes, one low-resolution pass for the strip and the analysis). Frame Grab is its
  own tool; Grade ("Frame from a video"), the Library, the Downloader and the Visualizer open it with the video
  loaded, and with a round trip the frame goes back to the tool that asked.
- Library (v2): one index of items (assets, exports, downloads, presets, looks) with
  their origin ("Made from"), uses and tags; files added from the PC are indexed where they are, never copied.
  A file keeps its identity (`fileKey`: volume + file index on Windows) when renamed or moved; a gone one is
  Missing until found or located. Collections: own folders (`Documents\Halation\Library\<name>`), PC folders
  linked, virtual collections, read-only packs. One panel (`libpanel.js`) for the Library page and the picker the
  tools open.
- Jobs: every heavy piece of work is a job in `jobs.js` (lanes `gpu`, `cpu`, `net`, `light`; priorities user,
  normal, background), shown in the title bar's island (`processes.js`); its outputs go to the Library.

## Inside a tool file

- Shared mutable state lives in one object (state section: `V` in Visualizer, `G` in Grade); bindings that are
  reassigned are `let` with a setter (`setS`, `setPresets`).
- A lower section that must call a higher one does it through `up` (state section), filled by the higher one with
  `Object.assign(up, { … })`.
- A name declared in two sections carries the section's name as a suffix (`draw_render`, `picture_media`).
- Nothing is global except what the tests and the other tabs use (`window.__halApp`, the API each tool gives the
  main window, set in its main section; `window.__halLastLayers` after a layer export).
## Adding a module

1. Its page: `app/dist/<id>.html` + `<id>.js` (an ES module with sections, or a classic script for a small
   tool), loading `i18n.js`, `common.js`, `icons.js`, `motion.js` like the others. Everything that animates goes
   through `motion.js` from the first component.
2. One entry in `MODULES` (`modules.js`): `id`, `icon` (Lucide name; add it to `scripts/lucide.js` and run it
   if `icons.js` lacks it), `src`, `group`, `home`, `heavy` if it holds a live canvas, `deps` (components it
   needs, `optional` if it works without them), `accepts` (kind → input handler of its API), `gives` (+ `result()`
   in its API) and `stage`. Its place in the list is its place on the rail.
3. Text: `tab.<id>` and `home.d.<id>` in `en.json`.
4. If it gives the main window an API (as `window.__halApp` in the frame) other tabs call it through
   `ensureApp(id)`; routes into it check `S.usable(id)` so a module turned off says so instead of opening.
5. A new downloadable component: an entry in `COMPONENTS`, its install in `tools.rs` / `tool_install`, its
   own copy in `storage.rs` (`own_path`, `components`) and the same in `tests/host.js`.
6. Tests: its flows, the scan tour (`tests/scan.js`), its segmented controls in `tests/segmented.js`
   (`FRAMES`), and `tests/run.js`'s allowed requests if it loads new files.

## Typed slider values (`common.js`)

- Any `<output>` in the same `.f` row as an `input[type=range]` (or `.lamt` in Grade, or named by the range's
  id through `for=`) is editable; nothing to register. The typed value goes back to the range with `input` and
  `change` events, so each page's own listeners do the rest.
- Scrubbers: a label with `data-scrub` (for a number or range field: its `for`, or the id in `data-scrub`)
  changes the value when dragged sideways (Shift ×10, Alt ÷10; `input` while dragging, one `change` at the end)
  and double-click puts back `data-def`.
- The number shown is the value multiplied by `data-scale` on the range (default 1); its unit is read from the shown text.

## Export (`encoder.js` + `encode.rs`)

- One module for every export that renders frames in the page (Visualizer layers). Frames go as raw RGBA
  (straight alpha, as `getImageData` gives them) over IPC to `encode_write`, a bounded queue of 3 frames, a writer
  thread and FFmpeg's stdin. One FFmpeg process per output file; progress from `-progress pipe:1`; `abort()` kills
  it and deletes the partial output. `x-rect` sends part of a frame, `x-same` repeats the previous one.
- API: `open(format, { file, width, height, fps, input, onProgress })`, `enc.write(bytes, rect?)`, `enc.same()`,
  `enc.finish()` → `{ path, size }`, `enc.abort()`, `estimate`, `freeSpace`, `folder`, `removeFolder`, `FORMATS`, `args`.
- Formats: `prores4444` (.mov, 16-bit alpha, default for transparent layers), `webm` (VP9 alpha, small), `h264`
  (opaque layers), `png` (sequence, last resort), `gray` (bass envelope), `wav` (24-bit). Video is BT.709 limited
  range, tagged the same.
- Output paths stay inside the Halation folder; `export_folder(name)` makes `Exports\Videos\<name>` (then `(2)`…).
  FFmpeg comes from `Tools\ffmpeg` or the PATH; if missing the export dialog offers the download.
- Visualizer layers: `01 Background.mp4` (H.264, vignette included), `02 Cover` and `03 Text` (alpha format),
  `04 Finish.mp4` (grain over 50 % grey for Overlay, only with "Separate overlay"), `05 Audio.wav`,
  `06 Bass envelope.mp4` + `.csv`, `IMPORT NOTES.txt`. The glow is a Normal layer with colour
  screen(background, glow); fades scale every layer. Each frame is rendered once into CPU canvases and every pass
  is written to its own FFmpeg at once. Size estimates: `layerBits` (bits per pixel and frame, measured).
  The opaque H.264 passes use CRF 16 so the ProRes stack recomposes within the tested mean error of 2/255;
  other H.264 uses keep their default. Layer encoders are bound to their job for cancellation.
- Tests: `tests/alpha.js` (each format composited over black, white and a checkerboard vs the canvas; a
  premultiplied control shows the halo), `tests/layers.js` (layers composited vs the full render, ffprobe),
  `tests/realapp.py` + `tests/selftest-encode.js` (real IPC on a debug build), `tests/measure-layers.js` (sizes).

## Motion (`motion.js`, `window.__motion`)

- Engine: GSAP + Flip (`gsap.min.js`, `Flip.min.js`, loaded before `motion.js` in every page), every move on one
  critically damped spring (`spring(v0)`); CSS only for press feedback, switches and the skeleton light. Details and
  reasons in `docs/MOTION.md`.

- Rules: `transform` and `opacity` animate, plus `filter: blur` for depth when changing place (hover colours are
  instant); a new animation starts from the current state of the running one and with its speed (`carry`); nothing
  waits for an animation; views with a live canvas change place without the blur (`flat`); `prefers-reduced-motion`
  or Settings → "Reduce animations" (`data-motion="reduce"` on `<html>` of every frame) turn every animation into a
  short fade. Every UI state change (appear, disappear, switch, reorder) goes through these primitives.
- Decorative backgrounds share a bounded clock; interactive motion retains its own clock. Auralis stays alive
  on focused visible Home with a tiny320px field at15Hz, and does zero work when suspended.
  Native focus overrides stale WebView document focus; minimize has an independent native signal.
  Static Atmosphere scenes remain invalidation-driven; dynamic scenes are paced. On Home the worker draws black,
  not microtexture; its softGrain belongs to tools. Auralis uses the approved stationary blue-noise at50% strength (approved2026-10-12) texture.
  Fullscreen cached crossfade/transform prototypes increased native GPU cost and were rejected. See
  `docs/performance/frame-budget-111/`.
- Visual review (`app/tests/visual-review.js`, attached by `common.openApp`) records viewport/DPR/CSS/canvas/iframe
  geometry and source provenance. Automated visual evidence is generated only on explicit request; ordinary visual
  iterations are reviewed in the actual local/native instance. Native frame timing and GPU counters are measured
  separately from deterministic rendered evidence. `encodeVideo` shares lossless RGB VP9/WebM encoding across
  renderers; validate decoded RGB frame hashes and presented browser frames against source PNGs when requested.
- Rules and tokens: `docs/MOTION.md`. Tokens (`tokens.css`): `--spring` 320 ms, `--place` 300 ms, `--fade` 140 ms,
  `--stagger` 28 ms (settle times), `--ease` (the spring as a CSS `linear()`), `--press-scale` 0.97, `--depth-blur` 6 px.
- Around the tools (`shell.js`): `enterApp` (the boot skeleton `#bootSkel` fades while the dock and the content come
  in), `birthOrigin` (a view grows from its dock icon), `preload` (hover or focus on a dock icon or a Home chip loads its
  tool), `whenReady` + `toolSkeleton` (`#toolSkel`: the tool's columns from `SKEL` until `__halApp.ready`; the page stays
  `.pending`, out of sight), `enterHome` (Home's pieces staggered).
- Primitives: `animate` (GSAP tween, one per element and channel), `fadeIn`, `scaleIn`, `fadeOut`,
  `show` / `hide`, `reveal(el, on)` (a control that appears with a choice), `enter` (a panel that replaced
  another), `pop` / `openPopover` / `closePopover` (menus from a button), `dialog(d)` + `d.showFrom(from)`,
  `flip` (Flip: moves while dragging), `list(container, mutate, { key })` (Flip, keyed lists: stay, scale in, fade out
  on a ghost), `details` / `autoDetails` / `toggle` (accordions without animating height), `swap` (views: the new one grows from its
  dock icon or from behind, the old one recedes out of focus or goes back into its icon), `slideTo`, `segmented` / `segmentAll` (one pill per `.tabs`/`.ltabs`, on the spring), `busy` (a tween still running),
  `bar` (progress with `translateX`; `.prog.indet` for an unknown length), `skeleton`, `stagger`, `spring`, `setReduce`, `reduced`. Busy work (Cutout, Remove Background, Frame Grab opening a video) shows a `.busynote` over a skeleton. CSS pieces live in `ui.css`.
- Tests: `tests/motion.js` (animations on: each primitive, the tool skeleton, places with depth, a performance trace
  with no task over 50 ms and frames per transition reported, fast repeated clicks, reduced motion as fades in every frame), `tests/segmented.js` (pill box equals the option's within 1 px
  in three languages and three widths). Functional suites run with reduced motion.

## Checking a refactor

- `node app/tests/baseline.js capture <dir>` before, again after, then `compare <before> <after>`:
  screenshots of the whole scan tour in English and Spanish (at most 0.4 % of pixels may differ by more than
  24 levels; two captures of the same build differ by up to 0.14 %), and 3 s exports of every kind (single
  video, ProRes and WebM layers, a Grade image) with the same streams and identical decoded frames.
- Plus `npm test`, `cargo clippy` (also `--target x86_64-pc-windows-msvc`), `cargo test` and
  `tests/realapp.py` on a debug build.

## Running the checks

- `app/tests/verify.js` (`npm run verify`; `npm test` without cargo) is the one entry point: cargo check → clippy →
  cargo test beside the Node test files, one fewer at a time than the machine has cores, longest first; then
  `motion.js` and `framegrab-perf.js` (their limits are timings) one by one with
  nothing else running.
- Global setup: fixtures made once by FFmpeg and copied per file (`fixtures.js`, cached in the temp folder by the
  hash of that file and the FFmpeg build), one static server for `dist/` (`HALATION_PORT`) and one browser per
  parallel slot (`HALATION_BROWSER`); `common.js` falls back to its own when a file runs alone.
- A check that passed is recorded in `app/node_modules/.cache/halation-verify.json` with the hash of what it
  reads (`app/dist`, `app/tests`, `package.json` and `$SHOTS` for the Node files; `app/src-tauri` for cargo) and
  is skipped while that hash stays the same; `--force` runs everything.
- Tests wait for conditions, never for a fixed time: `painted()` (fonts, images, no skeleton, two frames drawn in
  every visible frame) or the concrete state the next step reads. `motion.js` keeps its fixed pauses: they are the
  scenario (clicks mid-animation, transitions playing while the trace records), not waits.
